# Codex 打票账号范围

在管理后台「设置 → 网关转发」的 292 打票区域配置账号范围。

- 不指定账号：全部符合原规则的 OpenAI OAuth / setup-token 非影子账号，包括后续新增账号。
- 指定账号：仅对所选账号采票、注入和执行无票拦截；未选账号保持正常转发。
- 账号停用或删除不自动清空已保存的 ID，避免意外扩大到全部账号。
- 清空选择或取消最后一个选择时会要求确认；要完全停止功能，应关闭打票总开关。

账号范围通过 `openai_codex_ticket_account_ids` 保存到现有设置接口。
该字段是正整数数组，去重排序；`[]` 表示全部，不传字段保留原值。
保存后本实例失效缓存，其他实例最多约 5 秒重新读取；范围变化时在途采票结果丢弃。
配置文件的 `gateway.openai_codex_ticket.account_ids` 仅作为尚未保存后台设置时的默认值。

按账号和模型缓存、必须配置采票代理、默认无票拦截保持 PR #7315。
有效长度增加为 292 / 332（也保留配置文件显式指定的目标长度），同时要求 HTTP 200、`gAAAAA` 前缀和未过期；长度本身不是能力证明。
票据长度不是模型能力的官方保证；启用后采票会发起真实上游请求。

上线前停用并卸载旧打票插件，避免两个实现同时运行。升级不会自动打开打票总开关。

## 打票管理

点击同一设置区域的「打票管理」打开弹窗，集中查看「账号打票总览」与「打票日志与诊断」。展示已保存策略的状态，不使用尚未保存的表单值。关闭弹窗即停止刷新并取消未完成请求，再次打开重新加载。

- 总览按账号 / 模型显示有效票长度、到期时间、剩余时间以及无票时是否拦截；支持分页。
- 每次实际开始的采票记录账号名称 / ID、请求模型、票长度、HTTP 码、开始时间、成功 / 失败和诊断原因；没有 HTTP 响应时显示 `—`。
- 范围变更导致结果丢弃记为失败，不会作为成功票据展示。没有配置代理、未选中的账号及命中已有票据的跳过不算采票尝试。
- 日志写入 PostgreSQL，跨重启保留，账号删除后仍保留历史名称和 ID；仅保存元数据，不存凭证、代理 URL 或票据正文。
- 日志按新到旧分页，支持账号 ID / 结果筛选。计数按账号筛选，采票成功 / 失败不包括注入缺失。
- 问题账号是当前选中且激活、至少一个目标模型缺票的账号；不是历史失败账号数量。
- 注入缺失仅统计到达转发注入阶段时无票的事件，不包括调度器提前跳过的账号，避免把候选遍历当作实际请求。
- 可选每 15 秒刷新，默认关闭。历史日志不自动删除，长期高频失败时需关注数据库容量。写入异常会记录服务告警，但不改变原转发策略。

管理接口：`GET /api/v1/admin/settings/codex-tickets/overview`、`GET /api/v1/admin/settings/codex-tickets/logs`，均继承管理员认证。
部署时自动执行 `239_codex_ticket_logs.sql` 新建日志表，无需调整已有账号结构。
